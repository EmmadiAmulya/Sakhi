Love this — mapping the wiring before touching code is exactly the right move. Here's the full **frontend ↔ backend connection map** for Sakhi.

First, the key architectural insight that makes everything clearer: you have **two connection patterns**, and every feature falls into one of them.

- **🟢 Direct (browser → Supabase):** All user *data* (profile, cycle, journal, logs) goes straight from the client to Postgres, protected by **Row-Level Security**. No custom backend needed.
- **🔵 Proxied (browser → your Next.js server route → external service):** Anything involving a **secret key or RAG** (i.e., the AI). The NVIDIA NIM key must *never* touch the browser, so AI calls route through a server handler.

## 🔌 Connection map (by frontend surface)

| Frontend surface | Connection needed | Backend service | What flows / context |

## 🔑 Secrets & environment (who holds what)

- **Client-safe:** `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- **Server-only (never exposed):** `NVIDIA_NIM_API_KEY`, Supabase `SERVICE_ROLE_KEY` (admin tasks like ingestion), Web-Push `VAPID_PRIVATE_KEY`
- **Public push key:** `NEXT_PUBLIC_VAPID_PUBLIC_KEY`

## 🛡️ Cross-cutting connections (apply to all of the above)

- **RLS everywhere:** `using (auth.uid() = user_id) with check (auth.uid() = user_id)` on every user table.
- **AI endpoint hardening:** auth-check the server route, rate-limit it, and run Maya's safety filter (disclaimers + red-flag → helpline escalation) server-side.
- **Local-first sync (optional):** keep the Zustand store as an offline cache, sync to Supabase, reconcile on reconnect (ties into the Serwist PWA).

## 🪜 Suggested wiring order (low-risk → high-value)

1. **Auth** (magic link) + **profiles** — unblocks everything, replaces mock gate.
2. **Cycle + journal + logs** CRUD (direct Supabase + RLS) — migrate off local store.
3. **AI server route + Sakhi** (NIM, context assembly, streaming) — the first "real AI" moment.
4. **RAG ingestion + Maya** (embeddings + pgvector + citations) — the differentiator.
5. **Real reminders** (cron + web-push) — last, since it needs the scheduler infra.
